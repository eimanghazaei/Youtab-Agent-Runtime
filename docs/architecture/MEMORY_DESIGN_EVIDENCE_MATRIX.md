# Memory & Continuity — Design Evidence Matrix (item 7)

Primary/official sources mapped to explicit adopt/reject decisions. We borrow
*patterns*, never copy a framework into the Runtime. Every decision is judged
against One-Brain / N-Engines (Simorgh is the sole memory authority; engines are
replaceable) and against security + portability.

| Source (primary) | Pattern it establishes | Youtab ADOPTS | Youtab REJECTS | Why it fits One-Brain/N-Engines | Security / portability consequence |
|---|---|---|---|---|---|
| **OpenAI Agents SDK — Sessions** (`openai.github.io/openai-agents-python`, API ref `platform.openai.com/docs`) | Per-session conversation persistence keyed by session id, auto-loaded each turn | Session-scoped conversation persistence — already ours via `state.db` `sessions`/`messages` + `session_key`; Runtime keeps this as engine-local working context | Session store as the *authority* for organizational knowledge; treating conversation history as long-term memory | Conversation is engine-local working context, not sovereign memory — matches "Runtime owns working context; Simorgh owns authority" | Session data stays tenant/principal-scoped in `state.db`; no cross-tenant bleed; engine-swappable |
| **OpenAI sandbox / container memory** (`openai.com/index/gpt-5-1-codex-max`, container memory docs) | Durable *learned workspace memory* distinct from ephemeral session context | The distinction: durable learned memory ≠ session transcript. In Youtab durable learned memory is **Simorgh's**, reached via the MemoryBus; Runtime keeps only an encrypted scoped *cache* + outbox | A second durable learned-memory store living inside the Runtime (would be a second brain) | Keeps the single learned-memory authority in Simorgh; Runtime cache is a transport convenience, reconciled via outbox | Encrypted, scope-partitioned cache; erasure must reach it (ADR-0006 D7/D8); portable across engines because addressed by identity not engine |
| **LangGraph — persistence** (`docs.langchain.com/oss/python/langgraph/persistence`) | Three distinct concepts: **checkpointer** (thread execution state), **store** (long-term cross-thread memory), **pending writes** (durability of in-flight writes) | The 3-way separation as our ownership split: checkpointer→**Durable Execution owner**; store→**Simorgh authority** (Runtime consumes); pending writes→**Memory outbox** (idempotent, crash-safe) | Merging checkpointer and store into one Runtime component; using an in-process checkpointer as the durability authority | Cleanly maps to Simorgh(store) / Durable(checkpointer) / Runtime(outbox) — no component owns two authorities | Pending-writes/outbox gives at-least-once + idempotency + dead-letter (tested); checkpointer stays in the Durable owner where fencing lives |
| **Temporal — durable execution & Continue-As-New** (`docs.temporal.io/workflow-execution/continue-as-new`) | Durable event-sourced execution; Continue-As-New closes a bounded history and starts fresh from a compact state | Continue-as-new as the long-run pattern: a bounded segment ends with a canonical checkpoint, a fresh context resumes from it + retrieval (ADR references; `TaskCheckpoint` capsule shape) | Reimplementing a Temporal workflow engine inside Runtime; carrying an ever-growing transcript | Lets a task run for days and switch models without unbounded prompt growth; the *persistence* of that history is the Durable owner's, not Memory's | Model-neutral resume (content-addressed capsule); hostile-tamper integrity deferred to Durable owner (keyed/signed/fenced) — not claimed by a plain hash chain |
| **Youtab Simorgh ADRs** (in-tree `YOUTAB_AGENT_RUNTIME_BOUNDARY.md`; PROPOSED `ADR-0002 cognitive-growth`; Accepted `ADR-0002 simorgh-admission`) | One Brain is the sole cognitive/memory authority; signed admission envelope; governed promotion; five memory tiers | The boundary and the governed-promotion pipeline verbatim; MemoryClaim as transport envelope; promotion as Effect-Gate candidate | Any Runtime path that validates/promotes/supersedes/cross-shares canonical memory | This IS the One-Brain contract; ADR-0006 is additive and defers authority to it | Fail-closed on authority outage; provenance system-attributed; erasure/tombstone contract |
| **WP-13 federation** (Master Tracker; `tests/security/test_no_graphrag.py` on sibling branch) | LightRAG graph+vector federation MANDATORY; **Microsoft GraphRAG PROHIBITED** | Consume Simorgh's federated retrieval results; keep hybrid retrieval (lexical+vector+graph) on the authority side | Building GraphRAG or a second vector/graph authority inside Runtime | Federation is an authority-side (Simorgh) concern; Runtime only consumes scoped, ranked results | No second semantic brain in Runtime; portability preserved (retrieval is a contract, not an embedded engine) |

## Net design stance

- **Runtime owns:** working context, MemoryClaim transport DTO, scoped retrieval *consumption*,
  encrypted cache, outbox producer/consumer, token/context budget, continuity *references*.
- **Simorgh owns:** durable learned/semantic/episodic memory, validation, promotion, supersession,
  erasure policy, federated (LightRAG) retrieval.
- **Durable Execution owns:** checkpointer/persistence, leases, replay/resume, continue-as-new, terminal status.
- **Rejected across the board:** a second brain, a second vector/graph authority, GraphRAG, an
  in-Runtime durability authority, or copying any framework's engine into the Runtime.
